# 四题生成对照的预注册评分口径

以一次成功生成的一份可见答案为评分单位。四题各接受真实模型上下文和人工短证据，两款模型各重复三次，每款模型、每种上下文应有 12 份答案。题干、金标和上下文取自冻结输入，文件 SHA-256 为 `7ca3fe2425987318f7527c43fa243c4dcdeb76a69ea4e59cec0d51978099742b`。h03、h04、h05 使用应用的普通知识问答提示，h07 两组都使用联合比较提示。评分依据是每次提供给模型的编号片段。 [冻结输入](../context-coverage/release/generation-controls.jsonl) · [提示词及输出清洗](../../../core/llm_client.py)

## 两个独立记录的分数

- **语义通过**要求完整回答该题所问的所有要点，保留数值、单位、对象、条件和方向。主答复中有相互冲突的结论即计失败。额外的无依据断言或编号错误另记为严格失败。仅有部分要点时记录漏项，二元语义分为零。
- **严格通过**要求语义通过，且每一项实质性结论均能由所引片段支持。结论后的编号、同一句或紧邻的共同引用均可。多条结论共用一组引用时，各结论与相应片段的对应关系须清楚。越界引用、把邻行当作本行、声称原表有 TYP 值但该列为空、添加来源无法支持的器件行为，均计严格失败。数字恰好出现而参数角色不符，同样计失败。正文正确而结论反转计双项失败。语言和表述风格不计分。
- 每条保存语义分、严格分、失败原因和一段可定位的答案内容。主要结果对应用清洗后的可见答案评分；同一口径再核对模型原始可见正文，以识别清洗造成的变化。思考字段、引用修复或检索回退均属于不同阶段，不计入本次生成评分。

## 预算、清洗与统计

- 记录原始 `finish_reason` 和服务返回的 `completion_tokens`。`length` 表示服务报告生成因长度上限结束，仍对实际可见答复评分。半句话、高 token 用量和缺失编号可记为疑似截断；结束原因缺失则标记未知。正常结束但内容错误记为生成错误。原文有完整事实、清洗后丢失时单独记清洗损失。
- 若服务返回空正文且提供了生成记录，按实际空答案计分，同时标明是否有单独思考字段。连接失败或 HTTP 错误记录为服务异常，重试成功只占一个重复编号；单列计划数、成功数与失败数。每组只统计各题预定的前三个成功重复编号，不挑选更佳输出。
- 分别汇报每格通过数与实际分母、每题三次是否一致，以及相同上下文下的模型差值。h07 的真实输入含程序区间判断，短输入仅含两条电压范围；其长短差异同时受程序提示影响。四题均是先前定位的失败题，对照用于诊断生成，外推能力需由独立器件样本验收。
