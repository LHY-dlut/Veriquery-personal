# 全功能审查与问答修复验收

本轮复用 AutoDL 上保存的 datasheet-rag 评测索引。基线与修订版使用相同题目、索引和模型。首轮试验发现共享比较上下文仍会串器件，随后改成逐器件生成。所有入库、删除和坏库测试均使用隔离副本或可丢弃样本。

## 本轮改动

1. **比较题按器件取证并生成。** 明确比较且选择 2–8 个文档时，提取要比较的参数和工况，再各自检索、各自组装短证据和生成，最后按文档合并答案及引用。对供电比较补充 operating/single/dual supply 检索词，优先保留原文中明确写供电范围的片段。若模型误抄了明确范围，或 ADC 分辨率已有原句而模型缺引用，可返回标明“规格书原文”的摘录。某个文档缺少可引用依据时，单独标记该文档。 [比较检索和引用覆盖](../agents/workflow_nodes.py)
2. **限定一次引用修复。** 模型给出正文但缺少有效编号时，用同一份带编号证据校对草稿一次。对命名器件的供电范围，只有器件行和 `Vcc Range` 表头明确、且草稿等于原单元格字面值时，才允许直接关联来源。其他情况下引用仍不合规就返回证据不足。Trace 保留首答、修复输出和分器件实际送入的上下文。普通和流式接口都可在受控实例启用。 [字段与器件核验](../retrieval/table_evidence.py) · [生成与修复提示词](../core/llm_client.py) · [问答 trace](../api/routers/chat.py)
3. **保护数据与输出格式。** 将电路图片路由限制在配置的图片目录，限制图片类型并检查解析后的路径。SQLite 修复失败保留原库和已有 WAL，不在初始化时手动删除 WAL。在回答清洗中保留器件名、数字和单位边界，修复 LaTeX 中明确分隔的小数位。 [图片路径检查](../api/routers/circuit.py) · [SQLite 恢复](../core/sqlite_utils.py)

## 原题复测

在相同存量索引和 Qwen3.5-0.8B 下选取 8 道原题做定向回放。以下结论覆盖这些现象。本轮没有重新跑完整题集，模型在相同证据下的生成也有波动。最终源码包 SHA-256 为 `07abd552f5902b8872e28f7e15c9af344cef7581e32624fc6d210ee0ef383fc6`，本地 16 项回归通过。

| 题目 | 基线 | 最终回放 |
| --- | --- | --- |
| g033，比 OPA211 和 OPA188 的最大供电电压 | OPA211 给出 36 V，OPA188 被误判为 ±18 V | 两器件的实际单电源范围都进入各自证据，答案包含 OPA211 4.5–36 V、OPA188 4–36 V。OPA211 仍夹带未标明双电源条件的 18 V，整体按部分正确 |
| g081，比 MCP3008 和 MCP3421 的分辨率 | 这次基线给出 10/18 位，并夹入额外工况。较早的公开回放曾因无引用拒答 | 分别引用原文 `10-bit resolution` 和 `18-bit ΔΣ ADC`，两个器件的证据可分别复核 |
| g063，24LC256 供电范围 | 草稿是原表正确的 2.5–5.5 V，最终因缺引用拒答 | 确认器件行、VCC Range 列及字面值吻合后，返回 2.5–5.5 V 并引用对应表行。按厂商原文通过，原金标的 1.7–5.5 V 保持为冲突记录 |
| g045，24LC256 容量 | 拒答 | 最终给出 32K × 8、256 Kbit，并有支持引用。单次采样差异不能单独归因给修复 |
| g017，TMP117 供电范围 | 拒答 | 出现正确的 1.7–5.5 V，但把温区改写成供电范围。仍不满足验收 |
| g086，MCP3421 高精度转换的特征 | 拒答 | 执行一次引用修复后仍拒答 |

## 上下文和评测应该怎么改

- **对每个器件分别验收。** 比较题需要标注每个器件的参数和工况，而非只看文档是否出现。比如上一轮 g033 的 OPA188 文档已到上下文，供电范围缺席，失调电压反而出现。除了总 Recall@K，应记录每器件目标事实命中、所有器件覆盖率和最终上下文覆盖率。
- **保留短而完整的证据。** 当前通用问答最多取 8 段、约 4,200 字符。整表、正文中的重复表，以及不同工况可能同时出现。此前 TMP117 的 HEX 题在原文都已送达的情况下仍读错相邻行，精确行配合表头才有稳定的证据边界。无显式工况的普通题还需要减少重复、控制每段内容，并用固定索引验证证据覆盖。长上下文的位置变化本身也可能影响模型利用证据的概率。 [上一轮逐题证据](RANKED_TABLE_EVIDENCE.md) · [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)
- **先分层再计分。** 原文事实和金标先核对，再分别统计召回、入模、答案、引用和拒答。上次 g063 的 24LC256 原表是 2.5–5.5 V，金标是 1.7–5.5 V，另有一层是模型草稿答对原表但无引用。三个口径应独立保存。 [原题与原表核对](DATASHEET_GOLDEN_RESULTS.md#金标与原文的冲突)

## 微调的决策

当前优先修证据覆盖、上下文、引用协议。然后冻结同一批已审核的上下文，对现有模型和候选生成模型测准确率、错误拒答、引用正确性与延迟。比较应至少包含不同器件家族、两文档题、精确单位、无答案题及非法引用。当前模型若在相同、正确的上下文里仍稳定选错对象或数值，模型升级或针对输出行为的训练才有可检验的目标。

上游 datasheet-rag 用同一批冻结的 Dense+Rerank 上下文对照 Qwen3-4B 的基础模型与 QLoRA。在其 100 道题和 Judge 上，基础模型 + RAG 得 4.62/5，微调 + RAG 得 4.56/5。其 243 条合成训练样本也使闭卷拒答从 8/9 降到 3/9。这个结果支持先验证检索和生成行为。若最终需要训练，应针对“按器件写一行、单位与工况绑定、编号引用、合理拒答”，按器件家族分割训练和独立测试，避免把规格值当作模型权重中的事实库。 [上游 QLoRA 实验](https://github.com/palginpav/datasheet-rag/blob/885cbb4dacb633cc703cecad450c6be35a7b3668/docs/finetune-study.md)
