# 固定证据下的生成模型对照

选取默认配置中证据齐全、最终答复仍未严格通过的 h03、h04、h05、h07。四题涵盖总线读取位数、温区误差、关断时序和供电比较。每种模型各接收两种输入，每个组合生成三次。主要评分对象是项目清洗后、用户可以看到的生成正文。原始可见正文另行评分。 [四题与两种输入](../data/eval/context-coverage/release/generation-controls.jsonl) · [事先冻结的评分口径](../data/eval/generation-controls/rubric.md)

真实输入逐字复用保存的模型上下文，短输入取自此前人工核对的厂商事实。h07 的真实输入已附 5.0 V 区间核算，短输入只含两段供电范围。h07 长短差异同时涉及是否提供算术结论。h03、h04、h05 使用普通问答提示，h07 使用联合比较提示。推理请求固定为 256 个输出 token、temperature 0.1、top_p 0.9，三次独立调用未锁定随机种子。

两种模型均在原 AutoDL 实例通过 Xinference 的 Transformers 后端生成，使用 Qwen3.5 系列的未量化权重。保存每份请求、提示词哈希、返回模型 UID、原始消息、结束原因、token 用量与清洗结果。本实验隔离生成阶段，端到端表现仍需通过聊天接口验收。 [运行器](../data/eval/generation-controls/runner.py)

## 截断、清洗与时延

48 次 HTTP 生成均成功，服务全部报告 `stop`。4B 的 h04 真实上下文三次都恰好用满 256 个输出 token，原始正文都停在半句，标记为疑似截断。短证据三次都只用 82 个 token，仍然算错。0.8B 的 24 次均低于上限。逐条对比原始可见正文与清洗后答复，两档通过数均未变化。部分英文答案的标点与重复引用行确实被清洗改写。 [0.8B 原始记录](../data/eval/generation-controls/results/current.jsonl) · [4B 原始记录](../data/eval/generation-controls/results/stronger.jsonl)

真实上下文单次生成时延中位数分别为 3.37 秒（0.8B）和 2.93 秒（4B），对应输出 token 中位数分别为 156.5 和 89.5。短证据组分别为 2.85 秒和 2.30 秒。两种型号各自单独占用同一实例推理，输出长度不同，结果适用于本次问题和服务配置。4B 首次下载的两个权重文件共 9,319,828,096 字节，均已与官方 SHA-256 核对。 [0.8B 部署记录](../data/eval/generation-controls/results/current-config.json) · [4B 部署记录](../data/eval/generation-controls/results/stronger-config.json) · [4B 权重核验](../data/eval/generation-controls/results/stronger-weight-receipt.json) · [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)

## 工程判断

在完全相同的真实提示上，更换模型改善了位宽辨析和带引用的跨器件作答。短证据对 0.8B 的严格分提升更大。h04 表明更强模型也可能选对工况、读对上下界、执行错运算。建议优先用未调试器件验证 4B 在真实聊天 API 上的收益，并将数值问题的验收分到字段、工况、运算和引用四项。四道题均来自既有失败集，三次重复反映同题波动，证据范围限于生成诊断。
