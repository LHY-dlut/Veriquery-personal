# 新器件真实问答对照：MCP4725 与 TPS63020

这一轮测试 Qwen3.5-0.8B 和 Qwen3.5-4B 在完整 Veriquery 聊天链路中的表现。文档经真实上传接口入库一次，两臂查询同一批已就绪的文档，并调用 `POST /api/v1/chat/`。生成前后经过项目原有的检索、重排、上下文组织、引用校验、修复和拒答逻辑。

在查看答复前选定 Microchip MCP4725 原第 1、15 页和 TI TPS63020 原第 6、15 页。两份完整 PDF 均来自此前匹配原件哈希的本地语料；历史问答调试记录中未检出这两个器件。两家厂商的其他器件曾参与开发。四页分别覆盖 DAC 的工作范围与误差公式、转换器的电气特性与反馈电阻选型。结论范围为新器件和新选页。 [原文、页码与指纹](../data/eval/unseen-model-ab/sources.json) · [冻结题单](../data/eval/unseen-model-ab/questions.jsonl) · [评分细则](../data/eval/unseen-model-ab/rubric.md)

默认启用联合比较，上下文覆盖实验关闭。BGE 嵌入和重排、MinerU Advanced 结果和交付源码在两臂共用。每个模型依次回答 12 题，共重复三轮。每一轮每道题都使用独立会话。真实业务生成请求经本地记录器，登记实际请求和返回的生成模型 UID、提示词哈希、原始回答、结束原因和 token 用量。引用修复产生的后续请求另行保留。[实验协议](../data/eval/unseen-model-ab/protocol.md) · [真实接口回放驱动](../data/eval/unseen-model-ab/replay.py) · [推理调用记录器](../data/eval/unseen-model-ab/model_tap.py)

## 换模型的收益与代价

本次三轮共 72 次真实聊天均成功。MCP4725 和 TPS63020 分别产生 11 块与 53 块。Chroma 的 ID、文本、元数据和向量指纹，以及 BM25 和 SQLite 表记录指纹在两组一致。36 对回答的首个生成提示词哈希和实际模型上下文逐对相同。原始请求、返回 UID 与服务登记分别验证为 `qwen3.5`（0.8B）和 `qwen3.5-4b-eval`（4B）。

| 指标 | 0.8B | 4B |
| --- | ---: | ---: |
| 完整语义正确 | 5/36 | 15/36 |
| 严格通过，完整回答且有实际引用支持 | 4/36 | 13/36 |
| 10 道可答题，严格通过 | 1/30 | 11/30 |
| 6 道算术题，严格通过 | 1/18 | 3/18 |
| 两道部分可答题，完整报告已知值或工况并拒绝补造保证值 | 3/6 | 2/6 |
| 两道部分可答题，仅统计避免补造保证值 | 3/6 | 5/6 |
| 两道比较题，严格通过 | 0/6 | 3/6 |
| 聊天端到端 P50 / P95 | 5.24 / 6.53 秒 | 7.08 / 11.87 秒 |
| 实际生成调用，含引用修复 | 44 | 39 |
| 达到 256 token 输出上限的调用 | 23/44 | 19/39 |
| 模型加载后的整卡显存快照，含 BGE 服务 | 7474 MiB | 15060 MiB |

严格通过增加 9 个答复，即 25 个百分点。配对中有 12 个由失败转为通过，3 个由通过转为失败，1 个两边都通过，20 个两边都失败。按题计，三次里至少两次严格通过的题从 1/12 到 5/12。两道比较题与算术题的分母有重叠。结果按冻结口径对匿名混排的答复进行 AI 辅助复核。三次重复衡量同题波动，独立题目仍为 12 道。这两款器件支持部署候选决策，在整套产品上的收益仍需更广的样本。

**工程判断**：在这台已有足够显存的卡上，4B 值得作为规格读取与跨器件比较的生成模型候选。实测 P50 增加约 1.84 秒，P95 增加约 5.34 秒。算术题的 3 个严格通过全部来自同一道振荡器题。对依赖公式的自动计算，应优先保留公式和变量定义、核实输入与单位、确定运算后执行，再检查引用和答复是否完整。

## 公式到底丢在何处

首次解析的临时服务目录随服务关闭回收。为缩小故障范围，在主实验结束后按原件校验截取两张原第 15 页并单独用 Advanced 复解析。MCP 的三个公式与三个变量说明都以 `equation` 返回，TI 的反馈电阻式也以该类型返回。7 块内容都在适配器的 `full_text`，0 块进入供索引使用的 `page.text`。MCP 的三个分式和 TI 式 (3) 的括号、减 1 均可回对原件版面；首次入库文本的对应位置只保留标题或式号。复解析产物和首次索引分别保存。

代码路径也能解释这一现象。MinerU 客户端只把白名单文本块拼到正文，文档处理器采用正文再附加表行，后续分块使用这一字段。MCP4725 首页还有一处可补足 VREF=VDD 的片段，在三道 DAC 单器件计算题中排第 9，未进入 8 段上下文。优先修复方向为按版面顺序把公式及其变量定义编入带页码的可引用片段，再复测给模型的实际输入。 [原件公式坐标](../data/eval/unseen-model-ab/formula-source-audit.json) · [Advanced 原始块与适配正文对照](../data/eval/unseen-model-ab/results/formula-parser-replay.json) · [首次实际索引](../data/eval/unseen-model-ab/results/indexed.json) · [正文块类型白名单](../ingestion/mineru_client.py) · [应用正文构造](../ingestion/document_processor.py)

## 给足公式后，模型能否算完

六道算术题各用已冻结的厂家事实做一次独立短证据生成。这 12 次沿用 256 个输出 token，与 72 个真实聊天答复单独统计。两边都没有一份在这一单次诊断中完整通过。n07 在式 (3) 完整时仍出现照抄推荐值；n10 在两边操作数齐备时仍有 12 或 1024 步的错答。真实端到端回放的下游调用中，0.8B 有 23/44、4B 有 19/39 达到请求上限，实际结束原因都标为 `stop`，部分正文止于半句。 [0.8B 短证据](../data/eval/unseen-model-ab/results/arithmetic-probe-current.jsonl) · [4B 短证据](../data/eval/unseen-model-ab/results/arithmetic-probe-stronger.jsonl)

另针对两款模型在短证据下都触顶的三题 n02、n04、n06，使用相同提示、温度设为 0、top_p 设为 1，分别请求 256 和 768 个输出 token。这是事后预算诊断。六个长答原文均以同组 256-token 原文为完整前缀。延长后，4B 三道的数值都算对，n04 正文仍把器件型号写成 MCP425。0.8B 只算对 n06，n02 把十六进制换算成 3600 mV 而得到 3.6 V，n04 错设 LSB 为 1/12 V。短预算确实遮住了部分后续计算，更长预算也会让错误运算写得更完整。这些结果衡量的是数值过程，不计入主实验得分。 [0.8B 预算原文](../data/eval/unseen-model-ab/results/budget-current.jsonl) · [4B 预算原文](../data/eval/unseen-model-ab/results/budget-stronger.jsonl)
